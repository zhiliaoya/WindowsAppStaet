WindowsAppStaet
版本：v1.0.1

项目简介
WindowsAppStaet 是一款用于生成带优先级和延迟的 Windows 自动启动脚本的工具，同时内置了 系统启动项管理器，让您一站式管理所有开机自启项目。它解决了 Windows 系统开机自启无序性的问题，特别适用于需要优先启动某一程序（如提供运行环境、代理服务等）作为其他程序运行必须依赖项的场景。

典型使用场景
外贸工作场景：优先启动沟通工具（如 WhatsApp、Skype、微信等），确保与客户沟通无障碍

游戏场景：在启动 Steam 之前优先启动游戏加速器，避免因加速器启动慢导致游戏连接失败

开发环境：优先启动数据库服务，再启动 IDE 或其他依赖数据库的应用程序

企业办公：优先启动 VPN 客户端，再启动企业办公软件

功能特性
拖拽添加：支持将 .lnk（快捷方式）、.url（网址快捷方式）及其他文件直接拖拽到指定区域

单选勾选：在列表中只能勾选一个项作为第一启动项（优先启动项）

可配置延迟：设置第一启动项启动后等待的秒数（0‑300 秒），再启动其他程序

自动生成 BAT 脚本：根据用户配置生成批处理启动脚本

自动添加到启动目录：脚本生成后自动创建快捷方式到系统启动目录，实现开机自动运行

状态提示：底部状态栏实时显示操作反馈

🆕 管理脚本内容：在“生成启动脚本”标签页中，除了拖拽添加，还可通过 添加、编辑、删除 按钮直接管理要启动的程序列表；支持 备份 和 恢复 列表配置，方便保存和加载方案

🆕 管理电脑启动项：在“系统启动项管理”标签页中，可以查看、添加、删除、修改系统启动项（包括注册表 Run/RunOnce 和启动文件夹），支持 当前用户 和 所有用户 范围，并提供 一键备份/恢复 功能，助您安全管理系统开机自启程序

工作原理
生成启动脚本标签页：用户将需要自动启动的程序快捷方式拖拽到左侧区域（或通过“手动添加”按钮选择文件），右侧列表显示所有项，勾选需要优先启动的程序（单选），设置延迟时间。

点击「生成脚本」，程序将：

生成一个 BAT 批处理脚本

自动将该脚本的快捷方式添加到系统启动目录

系统启动项管理标签页：直接查看、添加、删除、修改系统注册表（Run/RunOnce）和启动文件夹中的项目，支持当前用户和所有用户，并提供备份/恢复功能。

下次开机时，系统会按配置的顺序自动启动所有程序。

生成的 BAT 脚本结构：

batch
@echo off
echo 正在启动第一程序：[优先启动的程序]
start "" "[程序路径]"
echo 第一程序已启动，等待X秒...
timeout /t X /nobreak >nul
echo 正在启动第2个程序：[程序B]
start "" "[程序B路径]"
...

使用步骤
脚本编辑：在“生成启动脚本”标签页中，将需要自动启动的程序快捷方式拖拽到左侧区域（或点击「手动添加」选择文件），右侧列表会显示添加的程序名称。

在列表中勾选需要优先启动的程序（只能勾选一个）。

设置延迟时间（优先启动程序启动后等待多少秒再启动其他程序）。

点击「生成脚本」，程序会自动生成 BAT 脚本并将其快捷方式添加到系统启动目录。

管理脚本内容：您可以使用「编辑选中项」修改名称或路径，使用「删除选中项」移除不需要的项目；使用「备份列表」将当前配置保存为文本文件，以后可通过「恢复备份」快速载入。

管理系统启动项：切换到「系统启动项管理」标签页，可以查看当前系统的所有启动项（包括注册表项和启动文件夹）。您可以：

添加：通过弹窗填写名称、命令（支持参数）和位置，新增一个启动项。

编辑：选中一个现有项，修改其名称、命令或位置。

删除：选中一个或多个项，批量删除。

备份：将当前所有启动项导出为文本文件。

恢复：从备份文件读取并写回系统（同名项会被覆盖）。对于需要管理员权限的项，程序会提示并以管理员身份重启动。

如何禁用自动启动？
按 Win + R，输入 shell:startup，打开当前用户的启动目录

删除对应脚本的快捷方式即可

注意事项
请确保拖拽的是有效的 .lnk（快捷方式）文件，否则程序会直接使用原始路径

支持 .url 网址快捷方式，会解析其中的 URL 地址

生成的 BAT 脚本保存在您选择的位置，请勿随意移动或删除

如果无法自动创建启动快捷方式，可以手动将生成的 .bat 文件拖入启动目录（shell:startup）

系统启动项管理功能涉及注册表操作，请谨慎使用。建议在进行删除或修改前先备份

涉及“所有用户”范围的操作需要管理员权限，程序会自动检测并提供提权提示

为什么不用 Windows 计划任务？
很多熟悉电脑的朋友可能会问：Windows 自带的「任务计划程序」不是也能实现开机启动和延迟执行吗？为什么还要专门做这个工具？

计划任务的局限性（对普通用户不友好）

问题	说明
操作复杂	需要打开管理工具、创建基本任务、设置触发器、配置操作……至少 5‑6 步才能完成一个程序的配置
延迟设置不直观	虽然可以通过「延迟任务时间」或「启动后等待」实现，但普通用户很难找到这些选项
多程序顺序依赖难配置	如果要实现「A 启动 → 等 15 秒 → 启动 B 和 C」，需要创建多个任务并配置依赖关系，极其繁琐
排错困难	任务执行失败时，日志分散、错误提示不友好，普通用户难以排查
权限问题	某些任务需要管理员权限，配置不当会导致任务不执行
实操对比：配置「先开加速器，再开 Steam」

步骤	Windows 计划任务	WindowsAppStaet
1	打开任务计划程序 → 创建基本任务	将两个快捷方式拖到工具中
2	输入任务名称「启动加速器」	勾选加速器作为第一启动项
3	选择触发器「登录时」	设置延迟时间（如 15 秒）
4	选择操作「启动程序」→ 选择加速器 exe	点击「生成脚本」
5	重复步骤 1‑4 创建 Steam 任务	自动完成（后续开机自动生效）
6	设置第二个任务延迟触发（需查教程）	—
7	测试、排错（可能需要修改任务属性）	—
总耗时	约 10‑15 分钟（且容易出错）	约 30 秒
本工具的优势总结

✅ 零学习成本——拖拽 + 勾选 + 点击，三步完成

✅ 可视化顺序管理——哪个先启动、等多久，一目了然

✅ 一键生成 + 自启动——无需手动配置触发器

✅ 状态实时反馈——哪里出错了马上知道

✅ 适合非技术用户——外贸人员、游戏玩家、普通办公用户都能轻松上手

计划任务更适合谁？

IT 专业人员、系统管理员

需要精细控制触发条件（如特定事件触发、每隔 X 小时执行）

需要配置复杂的执行条件（如仅当网络可用时执行）

简单来说：计划任务是为管理员设计的，而 WindowsAppStaet 是为普通人设计的。
