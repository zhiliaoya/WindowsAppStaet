# WindowsAppStaet

## 项目简介

**WindowsAppStaet** 是一款用于生成带优先级和延迟的 Windows
自动启动脚本的工具。它解决了 Windows
系统开机自启无序性的问题，特别适用于需要优先启动某一程序（如提供运行环境、代理服务等）作为其他程序运行必须依赖项的场景。

https://www.bilibili.com/video/BV1fxMx6fE83/?share_source=copy_web&vd_source=8f734f1e86c1b345adc07138e11bb4e1
\### 典型使用场景

1.  **外贸工作场景**：优先启动沟通工具（如
    WhatsApp、Skype、微信等），确保与客户沟通无障碍
2.  **游戏场景**：在启动 Steam
    之前优先启动游戏加速器，避免因加速器启动慢导致游戏连接失败
3.  **开发环境**：优先启动数据库服务，再启动 IDE
    或其他依赖数据库的应用程序
4.  **企业办公**：优先启动 VPN 客户端，再启动企业办公软件

## 功能特性

-   **拖拽添加**：支持将
    `.lnk`（快捷方式）、`.url`（网址快捷方式）及其他文件直接拖拽到指定区域
-   **单选勾选**：在列表中只能勾选一个项作为第一启动项（优先启动项）
-   **可配置延迟**：设置第一启动项启动后等待的秒数（0-300秒），再启动其他程序
-   **自动生成 BAT 脚本**：根据用户配置生成批处理启动脚本
-   **自动添加到启动目录**：脚本生成后自动创建快捷方式到系统启动目录，实现开机自动运行
-   **状态提示**：底部状态栏实时显示操作反馈

## 工作原理

1.  用户将需要自动启动的程序快捷方式拖拽到左侧区域
2.  在右侧列表中勾选需要优先启动的程序（只能勾选一个）
3.  设置优先启动后的等待时间
4.  点击「生成脚本」，程序将：
    -   生成一个 BAT 批处理脚本
    -   自动将该脚本的快捷方式添加到系统启动目录
5.  下次开机时，系统会按顺序自动启动所有程序

**生成的 BAT 脚本结构：**

``` batch
@echo off
echo 正在启动第一程序：[优先启动的程序]
start "" "[程序路径]"
echo 第一程序已启动，等待X秒...
timeout /t X /nobreak >nul
echo 正在启动第2个程序：[程序B]
start "" "[程序B路径]"
...
```

## 安装与使用

### 方式一：直接运行（需要 Visual Studio）

1.  克隆本仓库或下载源代码
2.  使用 Visual Studio 2017 或更高版本打开 `WindowsAppStaet.sln`
3.  编译并运行项目

### 方式二：直接使用可执行文件

1.  从
    [Releases](https://github.com/yourusername/WindowsAppStaet/releases)
    页面下载最新版本的 `WindowsAppStaet.exe`
2.  双击运行即可（无需安装）

### 使用步骤

1.  将需要自动启动的程序快捷方式拖拽到左侧「拖拽快捷方式到这里」区域
2.  右侧列表会显示添加的程序名称，勾选需要优先启动的程序
3.  设置延迟时间（优先启动程序启动后等待多少秒再启动其他程序）
4.  点击「生成脚本」，确认保存位置
5.  程序会自动将生成的脚本快捷方式添加到系统启动目录

### 如何禁用自动启动？

-   按 `Win + R`，输入 `shell:startup`，打开启动目录
-   删除对应脚本的快捷方式即可

## 注意事项

-   请确保拖拽的是有效的
    `.lnk`（快捷方式）文件，否则程序会直接使用原始路径
-   支持 `.url` 网址快捷方式，会解析其中的 URL 地址
-   生成的 BAT 脚本保存在您选择的位置，请勿随意移动或删除
-   如果无法自动创建启动快捷方式，可以手动将生成的 `.bat`
    文件拖入启动目录（`shell:startup`）

### 为什么不用 Windows 计划任务？

    很多熟悉电脑的朋友可能会问：Windows 自带的「任务计划程序」不是也能实现开机启动和延迟执行吗？为什么还要专门做这个工具？

    计划任务的局限性（对普通用户不友好）
    问题  说明
    操作复杂    需要打开管理工具、创建基本任务、设置触发器、配置操作……至少 5-6 步才能完成一个程序的配置
    延迟设置不直观 虽然可以通过「延迟任务时间」或「启动后等待」实现，但普通用户很难找到这些选项
    多程序顺序依赖难配置  如果要实现「A 启动 → 等 15 秒 → 启动 B 和 C」，需要创建多个任务并配置依赖关系，极其繁琐
    排错困难    任务执行失败时，日志分散、错误提示不友好，普通用户难以排查
    权限问题    某些任务需要管理员权限，配置不当会导致任务不执行
    实操对比：配置「先开加速器，再开 Steam」
    步骤  Windows 计划任务    WindowsAppStaet
    1   打开任务计划程序 → 创建基本任务   将两个快捷方式拖到工具中
    2   输入任务名称「启动加速器」   勾选加速器作为第一启动项
    3   选择触发器「登录时」  设置延迟时间（如 15 秒）
    4   选择操作「启动程序」→ 选择加速器 exe   点击「生成脚本」
    5   重复步骤 1-4 创建 Steam 任务    自动完成（后续开机自动生效）
    6   设置第二个任务延迟触发（需查教程）   —
    7   测试、排错（可能需要修改任务属性）   —
    总耗时 约 10-15 分钟（且容易出错）   约 30 秒
    本工具的优势总结
    ✅ 零学习成本——拖拽 + 勾选 + 点击，三步完成

    ✅ 可视化顺序管理——哪个先启动、等多久，一目了然

    ✅ 一键生成 + 自启动——无需手动配置触发器

    ✅ 状态实时反馈——哪里出错了马上知道

    ✅ 适合非技术用户——外贸人员、游戏玩家、普通办公用户都能轻松上手

    计划任务更适合谁？
    IT 专业人员、系统管理员

    需要精细控制触发条件（如特定事件触发、每隔 X 小时执行）

    需要配置复杂的执行条件（如仅当网络可用时执行）

    简单来说：计划任务是为管理员设计的，而 WindowsAppStaet 是为普通人设计的。

## v1.0.1 版本更新说明

v1.0.1
在原有「自动启动脚本生成」功能基础上进行了功能扩展，新增两个核心模块，并将原单页面界面升级为双标签页管理模式。

### 新增功能一：系统启动项管理

新增「系统启动项管理」标签页，可直接管理当前电脑中的 Windows
开机启动项目。

支持管理范围：

-   当前用户启动项
-   所有用户启动项

支持管理来源：

-   注册表 `Run`
-   注册表 `RunOnce`
-   Windows 启动文件夹

支持操作：

-   **新增**：创建新的系统启动项目，可设置名称、启动命令及位置
-   **删除**：删除不需要的开机启动项目
-   **修改**：编辑已有启动项的信息
-   **备份/恢复**：将当前启动项配置导出保存，并可从备份文件恢复

该模块让用户无需手动修改注册表或进入启动文件夹，即可通过可视化界面安全管理系统开机自启程序。

### 新增功能二：启动脚本内容管理

原版本只能通过拖拽方式添加启动程序，v1.0.1 增加了完整的列表管理功能。

在「生成启动脚本」标签页中新增：

-   **添加**：手动选择需要加入启动脚本的程序
-   **编辑**：修改已有启动项目名称或路径
-   **删除**：移除不需要启动的程序
-   **备份/恢复**：保存当前启动脚本列表配置，方便快速恢复启动方案

用户现在可以通过界面直接维护启动方案，无需重新拖拽添加。

### 界面升级

v1.0.1 将原有单页面界面重构为双标签页：

1.  **生成启动脚本**
    -   管理脚本执行顺序
    -   设置优先启动项
    -   配置启动延迟
    -   管理脚本内容
2.  **系统启动项管理**
    -   查看系统已有启动项目
    -   管理注册表启动项
    -   管理启动文件夹项目
    -   执行备份与恢复
